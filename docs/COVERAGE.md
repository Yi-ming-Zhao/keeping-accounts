# 实际覆盖与边界

0.2.1 新增通知与页面采集修复，验证范围见 [0.2.1 发布记录](RELEASE_0.2.1.md)。以下为 0.2.0 基础能力的既有验证；并不代表第三方应用所有真实路径已验收。

验证环境：ARM64 Android 16 模拟器，1260 × 2800，440 dpi。未连接 vivo X100 Pro；不推定 vivo 的系统版本、权限行为或后台保活。

## 系统服务端到端测试

独立 `fixtures` APK 显示真实 Android 文字节点并发布系统通知。青账仅通过自己的通知监听与无障碍服务采集；测试不直接调用解析器冒充服务触发。

| 场景 | 检查目标 |
|---|---|
| 京东式付款：商品10.00、优惠3.62、实付6.38 | 账本必须是638分，保留中性笔商品名 |
| 重开订单页 + 同订单通知 | 仅一笔，保留不同来源证据 |
| 拼多多式先用后付下单 | 28.80元显示为待扣款，不计支出 |
| 同订单扣款成功 | 原记录转为支出，仍只有一笔 |
| 系统支付通知 | 数据库存在 notification 渠道证据 |
| 同额8.80元、不同订单 | 保留两笔 |
| 待付款订单 | 不生成支出 |
| 撤销样本应用授权 | 页面、通知均不采集 |
| 地址与手机号混入订单页 | 持久化文字不含地址和手机号 |

这组样本证明采集服务能被系统真实触发，不证明第三方应用正在使用同样的文案或节点。

## 本地账本与真实模型

- 相同事件/支付号幂等；跨应用共同订单关联；分次付款不同支付号不合并。
- 未付款、部分退款、月付本金与手续费、校园充值、用户纠正锁、撤销、混合商品统计。
- 先用后付完整状态变化、未付款取消、旧金额冲突提示、未知金额人工确认。
- 密码加密备份恢复、错误密码不改账本、旧数据库迁移、中文 OCR 脱敏。
- 真正的 DeepSeek → 官方 Pi → Kotlin 原生工具 → SQLCipher：分类、商品、统计、两轮持续对话。
- UI 导航与编辑入口，Markdown 原生格式解析。结果记录在发布验收文档中。

## 仍需用户核对的情况

- 可见页面没有明确实付字段或出现冲突金额。
- 商品标题不可读、没有明确标签/语义节点；不能为了补商品上传整页私人信息。
- 重复页面没有共同编号，或微信扣款与拼多多订单使用不同编号。
- 第三方系统未发通知、页面未打开、无障碍被系统终止，或者页面受截图保护。
- 未知期初余额、缺少商品退款分配、没有实际交易时间、非人民币。

不自动发起支付测试，不操作支付应用按钮，不绕过保护。
