# 首版验收用例

测试使用合成脱敏数据或用户主动打开的历史订单，不自动发起付款。模拟器不用于声称通过 vivo 后台兼容性。

| 场景 | 必须满足的结果 |
|---|---|
| 同一支付通知重复发布 | 一条流水，重复事件不增加支出 |
| 同一商户连续两次同额付款 | 保留两笔，不仅凭金额和时间合并 |
| 淘宝订单跳转支付宝支付 | 有订单号或支付号证据才自动关联，统计一次 |
| 未付款订单 | 保存订单证据，不计入已发生支出 |
| 一个订单含食品和日用品 | 商品分别分类，合计不超过可证明的订单金额 |
| 缺失单价 | 不平均分摊或虚构单价 |
| 部分退款 | 关联原交易，保留原金额、退款金额及各自日期 |
| 美团月付消费后还款 | 消费计支出；还款减少欠款，不重复计支出 |
| 还款手续费 | 单独计支出 |
| 校园卡充值后消费 | 充值记账户转移，消费才计支出 |
| 小商户扫码只有金额和收款方 | 先记录付款，商品未知 |
| 个人转账用途不明 | 不推断商品或消费类别，进入待核对 |
| 非授权应用 | 不读取通知正文，不保存页面 |
| 授权应用聊天、登录、密码页 | 不持久化，也不发给模型 |
| 图片脱敏不可靠 | 不外发图片，不声称获得商品明细 |
| 系统禁止截图 | 记录采集限制，不绕过系统保护 |
| 断网或接口失败 | 已保存事件不丢失，任务可重试 |
| 工具提交后进程终止 | 从持久化状态恢复，避免重复写入 |
| 用户纠正分类 | 立即生效，后续自动处理不得覆盖 |
| 用户要求“以后都这样” | 明确保存规则，规则可查看、修改和删除 |
| 查询合计 | 原生数据库计算，与对应流水逐笔合计一致 |
| 备份密码错误或文件篡改 | 拒绝恢复，不改变现有账本 |

所有平台适配都必须区分：结构已支持、合成样本通过、真实应用验证通过。只有最后一项代表实际覆盖。
