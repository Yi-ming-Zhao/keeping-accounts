# 实现结构

## 交易数据

`capture/ReceiptParser.kt` 使用有边界的字段匹配和金额语义优先级。商品金额与优惠不能匹配“金额”。实付字段冲突保持未知；零元先用后付下单使用明确的待扣款金额。

`PaymentNotificationService` 和 `PaymentAccessibilityService` 先检查授权，再提取交易字段。页面稳定等待 700ms；语义清晰的商品/商户节点可补充字段。没有文字但存在交易页边界时可启用本机 OCR。受保护窗口截图失败即停止，不绕过。

`LedgerRepository` 负责事件、支付号、订单关联和证据关系。先用后付使用 `deferred` 状态，实际扣款转为 `expense`；未扣款订单取消不产生支出。金额相似本身不构成关联证据。原生层验证所有写入并保存修正历史。

## Agent 与对话

官方 Pi Agent Core 在 QuickJS 中运行；原生网络桥接兼容 Chat Completions。工具写入和执行凭据在同一数据库事务完成，恢复时避免重放同一写入。

`ConversationController` 在应用进程范围管理任务，界面导航不取消任务。`agent_runs` 保存官方 Pi 对话，界面只展示用户消息与最终回答；工具调用状态单独显示。失败和取消可以继续；新问题不会直接覆盖未完成的工具链。

`LedgerTools` 提供查询、统计、证据读取、分类、商品、退款关联和明确用户指令下的记账/纠正。金额用分；未知商户不能编造；模型价格必须有商品级证据。工具校验错误包含可执行的纠正建议。

`QueryPeriod` 在手机计算本月、上月、今天、近七日和指定月份，避免让模型换算 Unix 毫秒。合计在 SQL 中计算，分页查询不会冒充全量统计。

## 界面

账本、分析、对话、账户和设置五个入口。Compose 原生布局、系统字体、绿色主题。Markdown 由 Markwon 转为原生文本样式，支持表格和代码，不使用 WebView，也不自动获取远程图片。

详情可查看商品、优惠/运费、退款与证据，并编辑金额、商户、分类和备注。编辑保留撤销记录；“以后按此分类”独立保存为规则。

更新仅由用户点击发起，查询固定 GitHub 仓库的正式版本，语义比较版本号，再打开对应发布页下载。

## 存储与升级

数据库仍为 Room schema 3，0.2.0 未破坏已有表结构。对话复用现有 agent_runs 表。备份格式升级至 4，兼容格式 2/3，增加对话和工具凭据；密钥与图片不参与导出。

0.2.0 首次启动会用新版解析器复核已有文字证据。明确金额冲突进入待核对，用户修正锁不被自动覆盖。

正式 APK 使用原有签名；本地签名和模型配置均在 Git 忽略列表内。`fixtures` 是独立测试模块，不打包进正式应用。
